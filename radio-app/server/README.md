# Сервер «На связи»

Режим «Рядом» работает без этого сервера. Интернет-режиму нужен собственный постоянный сервер с HTTPS/WSS. Готовый IPA не разворачивает сервер автоматически.

```sh
python3 -m pip install -r requirements.txt
RADIO_ACCESS_TOKEN='случайный-секрет-не-короче-32-символов' HOST=127.0.0.1 python3 server.py
```

Направьте TLS reverse proxy на `127.0.0.1:8787`. В приложении укажите `wss://ваш-домен/ws#token=ваш-секрет`. Фрагмент после `#` преобразуется приложением в HTTP Authorization и не передаётся в URL серверных журналов. На обоих iPhone должны совпадать адрес сервера и код комнаты. Для кода комнаты рекомендуется не меньше 12 случайных символов.

Сервер хранит комнаты, участники, токены PTT и до 1,5 секунд сетевого аудиобуфера только в оперативной памяти. Аудиофайлы и история разговоров не создаются. Один активный говорящий на комнату; голос идёт небольшими пакетами во время удержания кнопки. Повторяющиеся данные не записываются после отпускания кнопки. Передача ограничена двумя минутами за одно удержание.

## Приём при заблокированном экране

Нужны подходящая подпись Apple с Push to Talk и Push Notifications, provision profile с этими возможностями, а также ключ APNs. Без них работает передача при открытом приложении; один IPA не может сам выдать эти права.

Необязательные переменные окружения:

```text
APNS_TEAM_ID=ваш-Team-ID
APNS_KEY_ID=ID-ключа-APNs
APNS_PRIVATE_KEY_PATH=/run/secrets/AuthKey.p8
APNS_BUNDLE_ID=app.nasvyazi.walkie
APNS_SANDBOX=0
```

Приложение отправляет полученный от PushToTalk временный токен только в памяти текущего канала. Сервер использует APNs `pushtotalk`, topic `<bundleID>.voip-ptt`, priority 10, expiration 0; его payload содержит `channelUUID` и `speakerName`. Подпись IPA другим bundle ID требует соответствующего изменения APNS_BUNDLE_ID и capabilities профиля.

Без APNs-настроек relay не прекращает работу: соединённые foreground-клиенты продолжают получать звук. Это не гарантирует пробуждение заблокированного iPhone.

## Протокол v1

Сервер присылает challenge nonce. Клиент отвечает hello с SHA-256 идентификатором комнаты, отдельным 32-байтным ключом комнаты, UUID, именем и HMAC-SHA256 от `nonce:id:room`. Передача ключа разрешена через TLS. Пользовательский код комнаты в plaintext не передаётся.

Control-сообщения JSON: `hello`, `welcome`, `peers`, `talk`, `pushToken`, `busy`, `error`. Binary frame: версия 1 (байт), тип 0 (байт), UUID отправителя (16 байт), UUID получателя либо нули для комнаты (16 байт), PCM-аудиопакет (не более 4096 байт). Relay проверяет UUID отправителя, право говорить, цель, размер и частоту пакетов. Сам аудиокодек задаёт iOS-клиент.

## Проверки

```sh
python3 -m unittest -v test_server.py
```

Тесты используют локальный ephemeral port, не обращаются в интернет и не отправляют APNs.
