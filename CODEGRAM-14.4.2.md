# CodeGram 14.4.2 / сервер 5.2.0

## Автоматическая история и сторис

В 14.4.1 автоматический запрос зависел от положения таблицы: при начальном смещении 0,
верхнем отступе навигации или чтении более старых записей таймер пропускал запрос.
Ручное «Обновить историю» показывало уже записанные VPS события, а не запускало их сбор.

Теперь открытая история запрашивает обновления каждые две секунды независимо от прокрутки
и загруженных старых страниц. Новые записи объединяются по seq, позиция чтения сохраняется,
а обновление изображения откладывается до окончания жеста. Неизменные данные не перерисовываются.
Чтение прекращается при уходе с экрана или в фон; старый ответ после отмены не меняет экран.

На VPS сторис обслуживаются отдельной очередью, которая не ждёт полного обхода аватарок и подарков.
Минимальный интервал — две секунды на профиль; общий темп запросов и FLOOD_WAIT сохраняются,
одновременно выполняются не более трёх RPC. Реальный интервал растёт с числом наблюдаемых профилей
и ограничениями Telegram. Полученные полные события и удаления по-прежнему записываются сразу.
Отдельно показываются последняя проверка сторис и её ошибка.

Это не гарантия захвата любой сторис, удалённой за две секунды: Telegram должен доставить событие
или предоставить содержимое до удаления. Приватность, недоставленные обновления и ограничения API
не обходятся. Статус чужой блокировки Telegram по-прежнему не раскрывает.

## Видео и конкретная ошибка со скриншота

Для коротких TikTok-ссылок используется GET с ограниченным HEAD fallback для совместимости.
Перенаправление повторно проверяется и остаётся внутри поддерживаемой платформы. Публичные HTTP CDN-потоки
теперь принимаются наряду с HTTPS; входная ссылка должна быть HTTPS. Проверка публичных сетевых адресов,
предел 250 МБ, ограниченная очередь и локальные file/pipe-входы ffmpeg сохранены.

Отдельно различаются DNS, извлечение страницы, отсутствие зависимости, запуск/остановка обработчика,
тайм-аут и некорректный MP4. Завершение по времени останавливает группу процессов, включая ffmpeg.
Диагностический вывод ограничен 64 КиБ и не передаётся в HTTP-ответ.

В окне ошибки отображаются безопасный код, версия службы, этап, код завершения и известный класс исключения.
«Скопировать ошибку» копирует только эту диагностику. Ссылка остаётся в черновике. Общая ошибка больше
не выдаётся за доказательство удаления ролика и не требует обновления службы при любом сбое.

Ссылка из скриншота использовалась в проверке настоящего обработчика. В среде проверки DNS TikTok недоступен:
прежний video_unavailable теперь определяется как video_dns_error на этапе resolve.
Это не диагноз сети владельца VPS и не подтверждение успешной загрузки этого ролика с его IP.
Если ошибка сохраняется, нужны скопированная диагностика и установленная версия службы.

## Удаление Liquid Glass

Классический режим форка включён принудительно с первого кадра и не возвращается к Glass из сохранённых настроек.
Общие материалы, навигация, карточки, поиск, кнопки и диалоги стали непрозрачными; отключены линза,
рефракция и стеклянные переходы. Прямые системные UIAlertController заменены матовыми диалогами.
Их ввод, отмена, динамический размер текста и прокрутка длинного сообщения сохранены.
В Watch-исходниках также удалены glassEffect; текущая неподписанная iPhone IPA не включает Watch-приложение.

Ключ UIDesignRequiresCompatibility не используется как решение: SDK 27 его игнорирует.
Окна, полностью рисуемые iOS вне приложения (системный выбор файлов, share/клавиатура),
не находятся под полным контролем публичных API форка. Принудительный классический режим относится к интерфейсу приложения.

## Обновление VPS

Вставить под root одну строку целиком. При другом домене заменить archive.mavasyaa.best своим:

```bash
apt-get update && apt-get install -y git ca-certificates && cg_dir=$(mktemp -d /tmp/codegram-v5.2.XXXXXX) && git clone --depth 1 --filter=blob:none --sparse --branch codex/codegram-14.4-links-profile-icons https://github.com/vaysenko7882/Nikita-iOS.git "$cg_dir" && git -C "$cg_dir" fetch --depth 1 origin 113e551e23e6b85d0aeb18aed807f67df041fc43 && git -C "$cg_dir" checkout --detach FETCH_HEAD && git -C "$cg_dir" sparse-checkout set server && bash "$cg_dir/server/install.sh" --domain archive.mavasyaa.best --reuse-session && /opt/nikita-archive/venv/bin/pip show nikita-archive && systemctl is-active nikita-archive
```

Ожидаются Version: 5.2.0 и active. Прежние сессия, ключ и база сохраняются.
Новую IPA установить поверх текущей с прежней подписью и bundle ID personal.nikita.messenger.

## Проверки

Прошли 130 серверных тестов на Python 3.10 и 3.11, 407 нативных тестов ядра
и 15 проверок скриптов сборки, конфигурации, кэша и упаковки иконок.
Нативная история прошла 30 проверок: 31 автоматическое HTTP-обновление, ни одного ручного.
После отключения краевых эффектов просмотрены все 210 кадров записи и 11 контрольных снимков;
снимки старых записей до и после новых событий и пакета 80+1 событий побитно совпали.

Регрессии сервера используют настоящий процесс обработчика, HTTP-потоки и ffmpeg, включая завершение дочерних процессов.
Нативный fixture использует производственный механизм истории и настоящий HTTP: новая сторис появляется
без кнопки обновления при смещении 0, прокрутке и открытых старых страницах; отдельно проверяются
пакет событий, готовность файла, отмена и фон/возврат. Матовые производственные компоненты записываются
в светлой и тёмной темах, включая длинную ошибку и ввод текста. Итоговые ссылки на CI и IPA — в PR.
