# Личный архив Никита на VPS

Служба входит отдельной сессией **в твой собственный Telegram-аккаунт** и постоянно получает его обновления. Она сохраняет текст сообщения перед каждой замеченной правкой и последнее содержимое перед удалением. iPhone забирает журнал при открытии клиента, затем каждые 30 секунд, пока приложение на экране. В чате удалённые сообщения полупрозрачны; история открывается долгим нажатием → «История изменений».

## Установка с iPhone

Нужны Ubuntu 22.04/24.04 или Debian 12+, SSH/веб-терминал своего VPS, свободные порты 80/443 и домен с A/AAAA-записью на этот сервер. Запись AAAA должна указывать на работающий IPv6; иначе убери её. Серверный API слушает только `127.0.0.1:8765`, наружу его выпускает Caddy с настоящим HTTPS.

В терминале VPS:

```bash
sudo apt-get update && sudo apt-get install -y git
git clone --depth 1 --filter=blob:none --sparse https://github.com/vaysenko7882/Nikita-iOS.git nikita-install
git -C nikita-install sparse-checkout set server
sudo bash nikita-install/server/install.sh
```

Установщик сам устанавливает зависимости. Если Caddy отсутствует в подключённых репозиториях Ubuntu/Debian,
он добавляет официальный подписанный stable-репозиторий Caddy. Пакетные вопросы о перезапуске служб
не прерывают установку; домен и вход в Telegram остаются интерактивными.

Установщик спросит:

1. Домен, например `archive.example.com`.
2. Твои **API ID и API hash** с https://my.telegram.org/apps — от того же личного API-приложения, что используется клиентом. API hash вводится скрыто.
3. Номер своего аккаунта, код из Telegram и, если включён, пароль 2FA. Пароль вводится скрыто. Эти данные вводятся **в твоём терминале VPS**, не в ChatGPT и не в HTTP-API.

В конце он покажет HTTPS-адрес и случайный **ключ доступа архива**. Это другой ключ, не API hash Telegram.

На iPhone: **Настройки → Никита → VPS и VoiceChanger → Интеграция с VPS**. Вставь адрес и ключ, нажми **«Сохранить настройки VPS»**, затем **«Проверить и синхронизировать»**. Аккаунт в клиенте должен совпадать с аккаунтом серверной сессии: при несовпадении импорт блокируется. Для каждого аккаунта iPhone хранит отдельные настройки; этот сервер обслуживает один аккаунт.

Не удаляй старую версию клиента перед установкой обновления: сохрани тот же bundle ID и подпиши тем же сертификатом, чтобы сохранить данные и локальный архив.

## Готовая сессия без нового кода

Если у тебя уже есть авторизованный файл `my_account.session`, созданный Telethon, положи его
на собственный VPS. Заверши скрипт, которым создавал сессию, прежде чем подключать её к архиву.
Файл сессии даёт доступ к аккаунту; не присылай его в чат и не выкладывай в репозиторий.

После скачивания исходников можно запустить:

```bash
sudo bash nikita-install/server/install.sh --domain archive.example.com --session /root/my_account.session
```

Замени домен и полный путь на свои. Домен в этом режиме повторно не спрашивается.
Установщик проверит формат и сделает согласованную SQLite-копию, включая зафиксированные WAL-данные.
Исходный файл и прежняя конфигурация остаются на месте, пока сессия не проверена.
Далее он проверит действительность ключа без `start()`, запроса кода или пароля и подключит
приватную копию к сервису. Ключ HTTP-архива сохраняется; смешивание разных аккаунтов блокируется.
Старую работающую службу установщик остановит на время переключения и запустит снова.

Если приватная конфигурация ещё не создана, понадобятся настоящие API ID/hash с
my.telegram.org/apps. Это параметры клиента; новый вход по номеру не выполняется.
Отозванная/незавершённая сессия, сессия бота, файл Pyrogram, tdata или StringSession отклоняются
с сообщением об ошибке. Установщик не будет автоматически запрашивать новый код.
Поддерживается стандартный SQLite-файл Telethon: https://docs.telethon.dev/en/stable/concepts/sessions.html

## Что сохраняется и какие есть ограничения

- Текст, подписи к вложениям, предыдущие версии текста и сведения о типе/имени вложения. **Сами фото, видео и аудио этот сервис не скачивает.** Если нужное вложение уже есть в локальном архиве iPhone, клиент продолжает использовать его локальную копию.
- Архив начинается с реально полученных сообщений. При первом запуске служба создаёт исходную копию последних 100 сообщений из 100 последних диалогов. Это число можно изменить в приватном `config.json`. Оно не восстанавливает сообщения, удалённые до установки.
- Telegram не гарантирует доставку каждого события удаления; офлайн-промежутки, рестарт VPS, отсутствие сети и ограничения API могут привести к пропускам. Последовательность правок, которую ни одна твоя сессия не успела получить, восстановить нельзя. Секретные чаты в серверную интеграцию не входят.
- На iPhone без VPS приложение запрашивает продление фоновой работы до 300 секунд и завершает задачу по сигналу iOS. **Это верхняя граница запроса, а не обещание пяти минут**. Система может дать лишь несколько десятков секунд. Принудительное закрытие прекращает работу iPhone; VPS продолжает независимо.
- Сервер сам не читает чаты с отправкой read receipts и не вызывает «печатает». Вход и другие клиенты могут менять видимый статус; полной невидимости сервер не обещает.
- VoiceChanger работает локально на iPhone и не отправляет голос на VPS. Эффекты: обычный, писклявый, мультяшный, низкий и робот. Эффект фиксируется в начале записи и применяется до кодирования Opus, включая предпросмотр. На звонки не влияет.

## Управление

Проверка службы:

```bash
sudo systemctl status nikita-archive --no-pager
sudo journalctl -u nikita-archive -n 50 --no-pager
```

Показать ключ повторно:

```bash
sudo -u nikita-archive /opt/nikita-archive/venv/bin/nikita-archive show-token
```

Остановить сбор новых сообщений:

```bash
sudo systemctl disable --now nikita-archive
```

Выключатель в iPhone отключает импорт на этом устройстве; сервер останавливается командой выше. Данные и сессия находятся в `/var/lib/nikita-archive/`, приватная конфигурация — `config.json` с правами 0600. Сессия Telegram даёт доступ к твоему аккаунту: не передавай эту папку или резервную копию другим. Для отзыва сессии используй Telegram → Настройки → Устройства → **Nikita Archive VPS** → Завершить сеанс.

Ключ устройства хранится в Keychain и не переносится резервной копией. На сервере нет веб-входа, удалённого выполнения команд, загрузки файлов или отправки сообщений: наружу доступно только чтение архива с bearer-ключом через HTTPS. Не публикуй ключ: его обладатель сможет читать серверный архив.

## Проверка разработчиком

```bash
python3 -m unittest discover -s server/tests -v
```

SQLite-журнал и HTTP-авторизация покрыты автономными тестами. Подключение к настоящему аккаунту, установка на конкретный VPS и поведение iPhone нужно проверять отдельно; автоматические тесты не заменяют эти проверки.
